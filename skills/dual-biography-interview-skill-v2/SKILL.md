# Dual-Output Biography Interview (v2)

Interviewing someone twice for the same material — once "for the archive" and again "for the book" — is exhausting for the narrator and produces a flatter second pass, since they're now performing rather than remembering. This variant produces both outputs from a single set of sessions by tagging as you go, rather than re-asking.

This builds directly on `biography-interview-kit-private-master` and `biography-interview-kit-public` — read both, plus the shared `../biography-memoir-system/references/interview-methodology.md`. What v2 adds is the tagging discipline that lets one interview branch into two outputs cleanly.

## Running the session: interview for completeness, tag for output

- Conduct every session the way `biography-interview-kit-private-master` would — full elicitation technique, no self-censoring on the narrator's behalf, pursuing sensitive material with consent.
- After each substantive answer (or in a quick pass at the end of the session), apply two tags, not one:
  1. **Reliability tag** (directly witnessed / told to them / family legend / reconstructed / uncertain) — same as every variant in this family.
  2. **Publication tag** (private-only / shareable-with-review / shareable-as-is) — same categories as `biography-interview-kit-public` uses, decided in conversation with the narrator right after the material comes up, while context is fresh, rather than in a separate review session weeks later when nuance is harder to reconstruct.
- If the narrator seems to be self-editing in real time because they're aware this might be shared, say explicitly: "Say it fully first — we'll decide together afterward whether it's for the archive only or for the book too." Protecting the completeness of the private record is the whole point of doing this in one pass instead of two.

## Producing the two outputs

- **Private archive**: everything, exactly as captured, with reliability tags — identical in spirit to the private-master kit's output.
- **Publishable draft**: only material tagged shareable-as-is or shareable-with-review (and, for the latter, only after the narrator's review pass), assembled the way `biography-interview-kit-public` specifies.
- Keep both outputs traceable to the same underlying session material so a later change in the narrator's publishing preference (something moves from private-only to shareable, or vice versa) is a re-tagging exercise, not a re-interview.

## What makes this genuinely different from just running both kits back to back

The failure mode this variant exists to prevent is a narrator giving two different accounts of the same event depending on which "mode" they think they're in — a guarded public version and a fuller private version that don't actually agree, which undermines trust in both. Interviewing once, for full material, and tagging afterward keeps a single ground truth that both outputs are drawn from.
