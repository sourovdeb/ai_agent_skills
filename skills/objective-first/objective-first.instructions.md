# Agent Instruction: objective-first

Source: skills/objective-first/SKILL.md (validated 2026-07-06).

## Role
Gatekeeper skill: no nontrivial work starts until the main aim and objective are written as an Objective Card and confirmed.

## Core rules
- The aim is a sentence naming the change, the beneficiary, and the measure; a topic is not an aim.
- A request phrased as a solution is traced back to the problem it serves before building.
- Deliverables without an objective above them are flagged as possible work for work's sake.
- The user owns the aim; the skill owns the questions. Never fill the card from guesses.
- One card per aim; multiple aims means multiple tasks.

## Workflow
1. Record the stated request verbatim.
2. Ask the aim question: what should be different in the world when this is done.
3. Separate aim, objective, deliverable; flag orphan deliverables.
4. Fill the Objective Card: aim, beneficiary, 2-4 verifiable success criteria, non-goals, hard constraints, kill condition, 15-minute first step.
5. Read the card back; challenge conflicts between criteria, deliverables that cannot reach the aim, and already-true kill conditions. Contested aims route to self-debate.
6. Place the card at the top of the task STATE file per Long_Task_Memory_Protocol.md.
7. During execution, check every step and every scope change against the card; renegotiate the card before accepting off-card work.
8. At completion, score the outcome against the success criteria on the card, not against effort spent.

## Constraints
- Maximum a few focused questions; this is a gate, not an interrogation.
- The card fits one page; longer means the aim is not yet understood.

## Activation
start a project, new task, help me plan, where do I begin, any solution-shaped request with no stated problem, scope drift mid-task, "do X" with no why.

## Output discipline
Output discipline: terse by default; expand only where the task requires. No contractions. No inline bold or italic. Formatting reserved for headings and structured data. No emojis. Improvement loop: append each session to OUTCOME-LOG; revise via skill-creator at ten sessions or a recurring failure pattern.
