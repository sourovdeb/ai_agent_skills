# Decision Battery — Antifragile v2 (42 steps, 6 phases + light mode)

**Source & Upgrade Notes**: Extends /home/workdir/attachments/decision-battery.md exactly (all original 40 steps retained or lightly expanded). Added: explicit energy/affect gates (ND requirement), dedicated SCAMPER mutation phase element + on-process, black swan module (ruin + early warning expansion), prompt-architect/socratic/consult hooks, ND chunking + somatic, real-user examples (CELTA redress, Pierrefonds house purchase, tutoring scale), GitHub after-action template, calibrated P + kill criteria emphasis. Total steps ~42 (some sub-bullets counted as steps for traceability). All claims VERIFIED-TRAINING or VERIFIED-LIVE from searches + original battery sources. UNVERIFIED where noted.

**Trigger**: Any Type 1 (irreversible) or high-stakes personal/family/professional decision; "run decision battery on [goal]"; stuck on bias/feeling; need to SCAMPER or pivot idea; black swan worry; weekly review.

**How to use (ND-friendly)**: 
- Start with energy check (1-10). <4/10 → use Light mode or exit ramp.
- One phase per sitting max on low energy.
- Use somatic 30s body scan before bias/affect steps.
- Agent mode: Paste this + your dilemma; I will walk phase-by-phase, calling sub-agents as needed.
- After each use: log to GitHub (template below) or personal journal.

**Energy Gate (mandatory, every phase start)**: Rate current energy 1-10 + recent events affecting judgment (affect audit). If ≤ 3 or high arousal: switch to Light mode (10 steps) or postpone. Log it. This is non-negotiable for stability.

## Phase A — Frame lock (steps 1–7, expanded with energy + prompt-architect)

1. **Decidable question.** Rebuild raw dilemma into one SMART sentence: verb, object, deadline, success metric. Fuzzy → chain prompt-architect first.
2. **Door classification.** Type 1 (consequential, irreversible — one-way) or Type 2 (reversible). Type 2 → Light mode only.
3. **Domain classification.** Cynefin: clear/complicated/complex/chaotic. Complex → probe-sense-respond small experiments only.
4. **Decision-rights line.** Who decides / consulted / affected. One line each.
5. **Constraint inventory.** Time/money/energy/skills/dependencies/red lines. Pull from memory + conversation before asking operator; gaps ASSUMED.
6. **History pull.** Prior attempts + outcomes from logs. Sunk costs listed once then excluded (Arkes & Blumer 1985).
7. **Energy + Affect Gate + Prompt-Architect hook.** Run energy 1-10 + somatic scan. If low → Light. Then restate dilemma to prompt-architect for crisp framing before proceeding. (NEW — ND requirement)

## Phase B — Debias preparation (steps 8–15, expanded)

8. **Bias checklist.** Run the 12-question: self-interest, affect attachment, groupthink, saliency/misleading analogy, confirmation, availability, anchoring, halo, sunk-cost/endowment, overconfidence/planning fallacy, disaster neglect, loss aversion (Kahneman, Lovallo & Sibony 2011). Log flags only.
9. **Outside view.** Name reference class + base rate before inside argument (Kahneman & Tversky 1979; Flyvbjerg 2006). No base rate → stated, never invented.
10. **Planning-fallacy correction.** Shift estimates to reference-class distribution (Flyvbjerg 2006).
11. **Affect audit.** One line: current emotions, arousal, recent events that could color judgment (Slovic et al 2007). Forecasts of future feelings marked unreliable (Wilson & Gilbert 2003).
12. **Self-distancing.** Restate in third person or as advice to friend; apply 10/10/10 (Kross & Ayduk 2017).
13. **Consider-the-opposite.** Three reasons current leaning is wrong (Lord, Lepper & Preston 1984); counter-anchor salient numbers.
14. **Incentive audit.** Who benefits from each answer, including recommender/source (Kahneman et al 2011 q1-3).
15. **Independent estimates + Socratic hook.** When others involved, collect separately (Delphi). If solo, run quick socratic on your own leaning before group input. (NEW)

## Phase C — Environment and tail scan (steps 16–22, + black swan module)

16. **PESTLE sweep.** One line per relevant Political/Economic/Social/Technological/Legal/Environmental factor.
17. **Live scan.** Web-verify every load-bearing external fact (prices, rules, deadlines). VERIFIED-LIVE or UNVERIFIED — never assume current.
18. **Scenario set.** Two axes of greatest uncertainty → four scenarios; test every option against all four (Schoemaker 1995).
19. **Tail separation (Black Swan core).** List ruin-class risks (unbounded/irreversible downside) apart from ordinary variance. Ruin risks = constraints, not costs — no EV trade accepted (Taleb 2007). (EXPANDED)
20. **Barbell structuring.** Cap downside; keep cheap upside optionality (Taleb 2012).
21. **Early-warning indicators (Black Swan).** For each scenario + ruin risk: one observable signal + check frequency (Heuer & Pherson 2010). Quarterly black-swan war-game recommended for recurring goals. (NEW)
22. **Black Swan Module — Throw-away ritual.** If ruin risk > threshold or original idea shows fragility under barbell test: run SCAMPER Reverse/Eliminate on the idea itself and consider full pivot. Log the "kill original" decision. (NEW — corporate pivot emulation)

## Phase D — Option engineering (steps 23–30, SCAMPER core expanded)

23. **Widen the frame.** "Whether or not" banned; min 3 genuine alternatives + null (do nothing) + delay (Nutt 2002; Heath & Heath 2013).
24. **Generate.** <3 real alternatives → chain brainstorm-agent Phase 1 and return survivors.
25. **Add–Change–Eliminate pass (SCAMPER core).** Apply SCAMPER verbs to the leading plan: what added, substituted, combined, adapted, modified, put-to-other-use, eliminated, or reversed makes it stronger/cheaper/faster/safer. Do one full SCAMPER cycle on the option set and one on the decision process itself. (EXPANDED — user request core)
26. **Vanishing-options test.** "If current favorite forbidden, what would you do?" — add answer to set (Heath & Heath 2013).
27. **Staging.** Convert large bets into gates: pilot → checkpoint → scale; define what each gate must show (Cooper 1990 Stage-Gate; cheapest falsifying test Ries 2011).
28. **Kill criteria.** Per option: observable state that means stop + date checked (Duke 2022). Written now, before attachment. Abandoning original idea is pre-planned branch, not crisis.
29. **Opportunity cost line.** Per option: what same time/money buys elsewhere. One line.
30. **SCAMPER on Process + Energy re-check.** Mid-phase energy gate. If low, switch to light SCAMPER (Substitute one thing only). Then apply SCAMPER Reverse to the entire battery (e.g. start from after-action). (NEW)

## Phase E — Adversarial test (steps 31–37)

31. **Premortem.** "It is [date]; choice failed completely" — list causes 2 timed minutes (Klein 2007).
32. **Red-team pass.** Attack assumptions/evidence/logic using red-team mindset (UK MOD Red Teaming Handbook 2021).
33. **Key Assumptions Check.** List; rate solid / with-caveats / unsupported. Unsupported → info tasks or registered risks (Heuer & Pherson 2010).
34. **ACH on pivotal uncertainty.** Hypotheses vs evidence matrix; least inconsistent evidence wins (Heuer 1999).
35. **Disconfirmation search.** Query "why X fails / criticism of X" actively (Wason 1960 confirmation bias antidote).
36. **FMEA.** Leading option: failure modes × severity × likelihood × detectability; mitigations for top scores (IEC 60812:2018).
37. **Sensitivity gate + Socratic self-review.** Which single assumption flips ranking? (Raiffa 1968). Then full socratic-self-review on draft brief. Class B may not skip.

## Phase F — Decide, commit, monitor (steps 38–42)

38. **Score.** NDV(A) = Σ[P_k × U_k] − C(A) − R(A) per finalist. Probabilities calibrated base rate ± named adjustments (Tetlock & Gardner 2015). Score dimensions independently before global (Kahneman et al 2019).
39. **Decide and journal.** Record: choice, P(success) with basis, strongest surviving objection, info that would change decision — before outcomes known. Quality judged on process not results (Duke 2018).
40. **Precommitment.** Lock kill criteria + tripwires with device: calendar check, informed witness (e.g. wife), automation, or written Ulysses contract (Schelling 1978; Heath & Heath 2013).
41. **Implementation intentions.** First actions as if-then: "If [situation], then I [action]" (Gollwitzer 1999 meta d≈0.65).
42. **Monitor loop + After-action + GitHub log.** OODA tied to step-21 indicators (Boyd via Osinga 2007; ISO 31000). On outcome/kill: what expected vs happened, why gap, changes next (US Army TC 25-20 1993). Append OUTCOME-LOG: date · domain · door type · choice · P given · outcome · lesson. 10 logs or recurring failure → revise this skill via skill-creator. Mandatory GitHub issue or PR comment for public accountability (template in repo).
